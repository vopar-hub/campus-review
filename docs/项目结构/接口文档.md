## 一、接口规范

### 1.1 统一响应格式

所有接口均返回统一的 JSON 响应格式:

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {},
  "requestId": "abc123-def456",
  "timestamp": 1711708800000
}
```

**字段说明**:

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 业务状态码，0 表示成功 |
| message | string | 提示信息 |
| data | object | 响应数据，失败时为 null |
| requestId | string | 请求唯一标识 |
| timestamp | long | 响应时间戳（毫秒） |

### 1.2 错误码定义

| 错误码 | 枚举值 | HTTP 状态码 | 说明 |
|--------|--------|-------------|------|
| 0 | OK | 200 | 成功 |
| 40000 | BAD_REQUEST | 400 | 请求参数错误 |
| 40100 | UNAUTHORIZED | 401 | 未登录或登录已过期 |
| 40300 | FORBIDDEN | 403 | 无权限访问 |
| 40400 | NOT_FOUND | 404 | 资源不存在 |
| 42900 | TOO_MANY_REQUESTS | 429 | 请求过于频繁 |
| 50000 | INTERNAL_ERROR | 500 | 服务器内部错误 |

### 1.3 认证机制

#### JWT Token 认证

系统使用 JWT (JSON Web Token) 进行身份认证。

**请求头格式**:
```
Authorization: Bearer <access_token>
```

**Token 有效期**:
- Access Token: 4 小时
- Refresh Token: 7 天

**白名单路径** (无需认证):
- `POST /api/auth/login`
- `POST /api/auth/register`
- `POST /api/auth/refresh`
- `GET /api/restaurants`
- `GET /api/restaurants/{id}`
- `GET /api/restaurants/by-ids`
- `GET /api/rankings/hot-restaurants`

**用户信息透传** (网关自动添加请求头):
```
X-User-Id: 123
X-User-Roles: USER,ADMIN
```

## 二、认证模块

**基础路径**: `/api/auth`

### 2.1 用户注册

**端点**: `POST /api/auth/register`

**认证**: 无需认证

**请求体**:
```json
{
  "email": "user@example.com",
  "studentNo": "2020001",
  "password": "password123",
  "nickname": "张三"
}
```

**请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| email | string | 是 | 邮箱地址，需符合邮箱格式 |
| studentNo | string | 是 | 学号 |
| password | string | 是 | 密码，长度 6-50 位 |
| nickname | string | 是 | 昵称，长度 1-50 位 |

**成功响应** (200):
```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "id": 1,
    "email": "user@example.com",
    "studentNo": "2020001",
    "nickname": "张三",
    "roles": ["USER"],
    "banned": false,
    "createdAt": "2026-03-29T10:00:00Z"
  },
  "requestId": "req-123",
  "timestamp": 1711708800000
}
```

**错误响应**:
- `40000`: 参数验证失败
- `40000`: 邮箱已被注册
- `40000`: 学号已被使用

---

### 2.2 用户登录

**端点**: `POST /api/auth/login`

**认证**: 无需认证

**请求体**:
```json
{
  "account": "user@example.com",
  "password": "password123"
}
```

**请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| account | string | 是 | 邮箱或学号 |
| password | string | 是 | 密码 |

**成功响应** (200):
```json
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "userId": 1,
    "roles": ["USER"],
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expiresAt": "2026-03-29T14:00:00Z",
    "refreshExpiresAt": "2026-04-05T10:00:00Z"
  },
  "requestId": "req-124",
  "timestamp": 1711708800000
}
```

**错误响应**:
- `40100`: 账号或密码错误
- `40300`: 账号已被封禁

## 附录

### A. 常见错误码速查

| 错误码 | 说明 | 解决方案 |
|--------|------|----------|
| 40000 | 参数错误 | 检查请求参数格式和必填项 |
| 40100 | 未认证 | 检查 Authorization 请求头 |
| 40300 | 无权限 | 检查用户角色权限 |
| 40400 | 资源不存在 | 检查资源 ID 是否正确 |
| 42900 | 请求频繁 | 降低请求频率 |
| 50000 | 服务器错误 | 联系管理员 |
