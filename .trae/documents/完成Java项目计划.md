# 类与方法注释计划（微服务优先）

## 目标

* 为仓库内所有 Java 类补齐注释：只在“类”和“方法”上写注释，不添加字段/行内/块注释。

* 执行顺序：先补齐各微服务模块（`campus-review-service` 下的各服务与网关模块），再补齐公共模块与其它模块。

* 交付结果：读代码时不需要跳转过多文件即可理解每个类的职责、每个方法的输入输出与关键约束。

## 注释范围与规则（统一口径）

### 1) 允许写注释的位置

* 类：`class/interface/enum/record` 使用 Javadoc（`/** ... */`）。

* 方法：`public/protected` 方法使用 Javadoc；`private` 方法在“复杂度高/易误用”时补齐（仍仅限方法级 Javadoc）。

* Override 方法：保留简短 Javadoc，说明扩展点含义与与父类/接口契约差异（若无差异可不写，避免重复）。

### 2) 禁止写注释的位置

* 字段、局部变量、代码块、行尾、import、包声明（不添加任何注释）。

### 3) 注释内容模板（按类型取舍）

* 类注释至少包含：职责/边界、所属微服务/领域、核心依赖（如调用的 client/mapper）、线程安全或状态性说明（如有）。

* 方法注释至少包含：用途、关键参数含义、返回值语义、异常/错误场景（抛出或返回错误码）、权限/鉴权/幂等性/事务性要求（如有）。

* 控制器方法：强调路由用途、鉴权要求、输入校验、主要响应含义。

* Service 方法：强调业务规则、幂等键、事务边界、外部依赖调用顺序（如关键）。

* Repository/Mapper：强调查询意图、索引/分页/排序约束（如明显）。

* 事件/消息处理：强调消息来源、幂等与重复消费处理、失败重试策略（如存在）。

## 执行顺序（从微服务到全仓库）

### 1) 微服务模块（优先）

* `campus-review-service` 聚合下的各服务模块（如 user/restaurant/review/interaction/ranking/notification/risk-control/admin）。

* `campus-review-gateway` 下的用户网关与后台网关（路由、过滤器、鉴权与异常转换相关类优先）。

* 每个模块按分层顺序补齐：Controller → Service → Client/Feign → Repository/Mapper → Config/Filter → DTO/VO/Enum（若分布在该模块内）。

### 2) 公共与基础模块（后续）

* `common/model/utils/feign-api` 等公共模块：优先补齐对外暴露的 API、异常与通用工具类的类/方法注释。

* test/basic 等模块：只补齐有复用价值或容易误用的核心类与公共测试工具类。

## 质量校验

* 只使用 Javadoc 注释；不引入新的注释风格混用。

* 注释不重复代码字面信息：避免“getX returns x”式无信息增量描述。

* 注释与签名一致：参数名、返回语义、异常与权限要求保持同步。

* 最终以全量编译通过为准（注释不应引入格式或语法错误）。
