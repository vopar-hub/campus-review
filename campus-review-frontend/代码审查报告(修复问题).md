## 详细修复说明

### 1. Cookie 安全设置 (`src/utils/storage.ts`)

**修复前**:
```typescript
Cookies.set(TOKEN_KEY, token, { expires: 7 })
```

**修复后**:
```typescript
Cookies.set(TOKEN_KEY, token, {
  expires: 7,
  secure: import.meta.env.PROD,
  sameSite: 'Strict'
})
```

**原因**:
- `secure: true` 确保 Cookie 仅通过 HTTPS 传输（生产环境）
- `sameSite: 'Strict'` 防止 CSRF 攻击

---

### 2. 路由守卫竞态条件 (`src/router/index.ts`)

**修复前**:
```typescript
setTimeout(() => {
  if (!userStore.isAdmin) {
    ElMessage.error('无权访问')
    next({ name: 'home' })
  } else {
    next()
  }
}, 100)
```

**修复后**:
```typescript
if (!userStore.user && hasToken) {
  try {
    await userStore.fetchUserInfo()
  } catch (error) {
    ElMessage.error('用户信息加载失败，请重新登录')
    next({ name: 'login' })
    return
  }
}
if (!userStore.isAdmin) {
  ElMessage.error('无权访问')
  next({ name: 'home' })
  return
}
```

**原因**: `setTimeout` 是竞态条件 hack，不可靠。应使用异步等待确保用户信息加载完成。

---

### 3. 错误处理统一 (`src/api/admin-request.ts`)

**修复前**:
```typescript
return Promise.reject(new Error(res.message))
```

**修复后**:
```typescript
return Promise.reject(new BusinessError(res.code, res.message, res.requestId || null))
```

**原因**: 保持与 `request.ts` 一致，便于调用方统一处理错误。

---

### 4. 拦截器反模式修复 (`src/api/admin-request.ts`)

**修复前**:
```typescript
const userStore = useUserStore()
const roles = userStore.user?.roles?.join(',') || 'USER'
```

**修复后**:
```typescript
// 移除 useUserStore() 调用
if (!config.headers['X-User-Roles']) {
  config.headers['X-User-Roles'] = 'USER'
}
```

**原因**: 在请求拦截器中调用 Pinia Store 是反模式，可能导致 store 初始化竞态。

---

### 5. ESM 兼容性 (`vite.config.ts`)

**修复前**:
```typescript
import { resolve } from 'path'
'@': resolve(__dirname, 'src')
```

**修复后**:
```typescript
import { resolve, dirname } from 'path'
import { fileURLToPath } from 'url'
const __dirname = dirname(fileURLToPath(import.meta.url))
```

**原因**: ESM 模式下 `__dirname` 不可用。
